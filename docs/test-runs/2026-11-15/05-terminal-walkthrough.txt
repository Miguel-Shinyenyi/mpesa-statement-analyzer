UMWAYI-OS: THE TERMINAL WALKTHROUGH
Script for a 4 minute 30 second video. Narration, what is on screen, and the real output.

HOW TO USE THIS FILE
- The terminal parts are best recorded for real, not generated. A video model draws text badly, and a command with one wrong letter looks fake. File 06 shows how to record the real terminal in one command. The commands in this file ran on umwayi-os main (after PR 96) and the output below is what they printed.
- Muse Video is the right tool for the short scene cards between terminal parts (the shepherd, the gate, the highlands). Paste the prompts marked MUSE. They use the STYLE, SHEPHERD and SOUND tags from file 04.
- Put your voice over everything in your editor. The VOICE lines are written to be read aloud, short, one idea each.

LENGTH AND PACE
- Total 4:30. Eight scenes. Each terminal scene is 20 to 35 seconds. Each card is 6 to 10 seconds.
- Type slowly. Leave 3 seconds after each output so the viewer can read it.

SCENE 0. COLD OPEN (0:00 to 0:15)
MUSE (10 s clip): STYLE. The Kenyan highlands at dusk, a lone shepherd with a staff stands by a stone gate, sheep wait behind it. The lamp on the gate post is amber.
SCREEN TEXT: umwayi-os. An AI operating system for one person.
VOICE: "You hand work to AI helpers. They are fast, and they do not stop to ask. umwayi-os puts your rules in front of every one of them."

SCENE 1. THE GATE: YES, NO, ASK ME FIRST (0:15 to 0:55)
SCREEN: terminal.
  $ umwayi --version
  umwayi 0.1.0
  $ umwayi check '{"type":"read_memory"}'
  Yes
  Rule: read-memory
  Reason: Reading the memory folder through the loader is allowed.
  [exit 0]
  $ umwayi check '{"type":"git_push","branch":"main"}'
  No
  Rule: no-push-main
  Reason: Nothing is pushed to the main branch. Cause: Work happens on feature branches with pull requests.
  [exit 2]
  $ umwayi check '{"type":"deploy","target":"prod"}'
  Ask me first
  Rule: (none)
  Reason: No rule matches this action.
  [exit 3]
VOICE: "Every action gets one of three answers. Yes. No. Or Ask me first. Reading memory is allowed. Pushing to main is refused. A deploy has no rule, so it asks me. If a rule is missing, the answer is never yes. And a crash counts as no."
ON SCREEN CAPTION: Exit 0 yes, 2 no, 3 ask me first. Never 1.

SCENE 2. ASK ME FIRST BECOMES A QUESTION (0:55 to 1:25)
SCREEN:

  Added Q-0001 (decision): Deploy to prod?
  $ umwayi queue list
  Q-0001  decision  open  -  Deploy to prod?  [recommendation: No, deploy from a branch]
VOICE: "A question I need to answer lands in a queue. Every question carries a recommendation. The helper waits. It does not guess."

SCENE 3. THE LOGBOOK YOU CAN VERIFY (1:25 to 1:55)
SCREEN:

  ok: 5 entries, the format is valid and the hash matches the record

MUSE (8 s card, optional): STYLE. A tall standing stone at dusk with a glowing bead helix wound around it, one bead lit.

SCENE 4. THE KILL SWITCH (1:55 to 2:20)

VOICE: "One file stops everything. If umwayi cannot read the switch, it treats it as on."

WHAT TO SAY NO TO IN THE EDIT
- Do not show the tool names as if all three were run for real. Show a caption: "Tested with fakes. Real runs are on my checklist."
- Do not show the web page scene as a live product. It runs on sample data.
- Do not read the exit codes aloud more than once.

CHECKLIST BEFORE YOU RECORD
- Run from the umwayi-os repo root, on a branch with the newest main.
- bash demo.sh makes a scratch root and deletes nothing.
- A real terminal at 1600 by 900 reads best on phones. Font size 22 or larger.
